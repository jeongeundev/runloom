# Phase 23 — 설정 UX: 처음 온 관리자가 화면만으로 팀·종류·담당·저장소를 준비한다

작성일: 2026-10-05. 상태: 설계 완료, 실행 전. **`service`(22 결과 뒤 판단 병합 `058d9bc`, 스키마 v24)에서 실행한다.** 병합은 phase 뒤 사용자 지시로(`--no-ff`). 근거: [사내 요청 실연동 1회차](../../docs/product/INTERNAL_REQUEST_LIVE_RUN_1.md) "결과"(화면 점검 15건), [UI_GUIDE](../../docs/UI_GUIDE.md), [ADR-0009](../../docs/adr/0009-registered-kinds-and-succession-rules.md)(종류·후속 규칙은 등록 데이터), [ADR-0022](../../docs/adr/0022-work-screen-and-direct-work.md)(업무 화면), [ADR-0025](../../docs/adr/0025-triage.md)(판단), [ADR-0027](../../docs/adr/0027-next-step-triage.md)(결과 뒤 판단), [담당 범위 표](../../docs/product/RESPONSIBILITY_DIRECTORY.md).

## 왜

2026-10-05 공개 사례 K1 실연동을 셀프호스트(v24)에서 시작했지만 **준비 1번(팀 초대)에서 멈췄다**. 사용자 평: "보기가 너무 어려운데. 팀 초대하는것도 어렵고 그냥 하나부터 열까지 ux 개판". 이어서 관리자 계정으로 준비 화면을 돌며 찾은 문제 15건(1회차 문서 "화면 점검에서 나온 문제"):

- **찾기** — 팀 초대가 "연결" 메뉴의 "팀·담당자" 탭 안에 있다(메뉴에 "팀" 없음). "연결" 첫 탭이 저장소 카드 + 이슈 목록 전체(업무 화면과 중복) + Jira + n8n 토큰·curl 예시로 4000px 를 넘는다. 판단 에이전트 지정이 저장소 카드 "고급 설정" 접힘 안에 있고, 결과 뒤 판단도 이 칸이 켠다는 설명이 없다.
- **초대** — 링크는 만든 직후 한 번만 보이고 목록엔 `inv-…` ID 만 남는다. 누구에게 보낸 초대인지 모른다. 팀 탭 맨 위 빨간 `WORKFLOW_PUBLIC_URL` 경고가 늘 떠 오류처럼 보인다.
- **내부 값 노출** — 에이전트 표의 `agt-…`·`code.fix · repository_id=…`, 저장소 카드 select 의 `(agt-…)`. 종류 등록 폼이 kind 식별자·능력 코드·scope_key·산출물 체크박스 19개(`codex_stderr` 등)를 요구한다. 담당 범위 폼이 "시스템 식별자"·"요청 유형 식별자" 자유 입력(좁은 칸). 저장소 고급 설정이 "GitHub 사용자 숫자 ID" 를 요구한다.
- **업무 목록** — 필터 네 묶음 + 저장소 select + [보기] 버튼. 빠른 필터 "담당 없음 20" 과 묶음 머리 "담당 없음 22" 가 다르다. 우선순위(모두 보통)·종류(모두 버그 수정) 칸이 정보 없이 자리를 차지하고, 상태 "새로 들어옴" 과 다음 할 일 "담당 없음" 이 같은 말을 반복한다. 에이전트 표의 맡기기 칸이 좁아 버튼이 세로로 깨진다.

K1 은 이 phase 뒤로 보류했다. 이 phase 가 끝나면 관리자가 **문서 없이 화면만 보고** 멤버 둘 초대 → 조사 종류 등록(맡을 에이전트 선택) → 담당 범위 추가 → 저장소에 판단 에이전트 지정까지 할 수 있어야 한다.

## 사용자 결정 (2026-10-05)

1. **D1 범위** — 설정 화면 + 업무 목록 정리. 점검 15건만 고친다. 저장소(프로젝트)별 판단 기준은 다음 phase.
2. **D2 메뉴** — 팀·저장소를 메뉴로 꺼낸다. 사이드바 `업무` · `받은·보낸 요청` · `모니터링` · `팀` · `저장소` · `설정` · `내 설정`(+ 조건부 `시작하기`). `팀` = 멤버·초대·에이전트·담당 범위. `저장소` = 저장소 카드(이슈 목록은 빼고 업무 화면으로). `설정` = 종류·규칙·판단·알림·n8n 입구·고급.
3. **D3 초대** — 초대할 때 받는 사람 이메일(필수)·이름(선택)을 적는다. 목록은 이메일로 보인다. 링크를 놓치면 그 줄에서 [링크 다시 만들기] — 옛 링크는 무효. 링크 원본은 지금처럼 저장하지 않는다(해시만).
4. **D4 종류의 맡을 에이전트** — 종류 등록 폼에서 "이 일을 맡을 에이전트" 를 체크박스로 고른다. 고른 에이전트에 그 종류의 능력을 붙인다. 능력 코드·scope_key·산출물 칸은 자동으로 채우고 "고급" 으로 접는다.

## 계획 기본값 (step 0 이 ADR-0028 로 고정 — 코드 근거가 있으면 바꾸고 이유를 남긴다)

1. **주소.** 새 GET 주소 `/team`(지금은 303 → `/connect?tab=team` — 이 phase 에서 실제 화면이 된다), `/repos`, `/settings?tab=kinds|triage|notify|inbound|advanced`. `/connect` 와 `/connect?tab=…` 는 새 주소로 303(탭 → 주소 표는 step 0). 옛 주소(`/sources`·`/operator`·`/operator/github`·`/operator/notifications`·`/agents`·`/kinds`)의 303 대상도 새 주소로. **POST 경로는 바꾸지 않는다**(GitHub App 콜백·설치 경로·폼 action 그대로) — POST 뒤 303 대상만 새 화면으로. 사이드바 활성 표시는 경로 접두사.
2. **권한.** 지금 탭별 권한(`CONNECT_TABS`)을 화면·절 단위로 옮긴다. `팀`·`저장소` 는 로그인 멤버 누구나 보고 바꾸는 동작은 지금 권한 그대로(`manage_team`·`manage_connections`·`manage_rules`·`attach_runner`). `설정` 의 판단 탭 `manage_connections`, 알림 탭 `manage_shared_notify`. 권한 없는 탭·절은 숨긴다.
3. **초대 스키마 v25.** `member_invites` 에 `invitee_email TEXT`(초대만 필수 — 재설정 링크 행은 NULL), `invitee_name TEXT`(NULL 허용) 칸을 더한다(ALTER — 다른 표는 건드리지 않는다). 기존 열린 초대는 이메일 NULL 로 남고 목록에 "이메일 없음(옛 초대)" 로 보인다. `repo.issue_invite(conn, *, session_id, role, invitee_email, invitee_name, created_by_member_id, now) -> tuple[str, str]`(invite_id, token), `repo.reissue_invite(conn, *, invite_id, now) -> str`(같은 행의 `token_sha256`·`expires_at` 을 새 값으로 — 사용·취소·만료된 초대는 거부). 같은 워크스페이스의 활성 멤버 이메일·열린 초대 이메일과 겹치면 거부. 가입 화면은 초대 이메일을 채워 고정하고 가입 시 그 이메일로만 만든다.
4. **초대 화면.** `팀` 화면 멤버 절 아래 "초대": 이메일·이름·역할 + [초대 링크 만들기]. 만든 직후 링크 + [복사] + 안내 "이 링크는 지금만 보입니다. 놓치면 목록에서 [링크 다시 만들기]". 대기 중 초대 줄 = `이메일 · 이름 · 역할 · 만료` + [링크 다시 만들기] + [취소]. `WORKFLOW_PUBLIC_URL` 미설정 안내는 빨간 `.alert` 가 아니라 링크 바로 아래 회색 안내 한 줄("이 링크는 이 컴퓨터 주소 기준입니다 — 다른 컴퓨터에서 열려면 SELFHOST 문서의 WORKFLOW_PUBLIC_URL").
5. **에이전트 능력 하나씩.** `repo.add_agent_capability(conn, *, agent_id, capability: Capability) -> bool`(이미 있으면 False, 멱등), `repo.remove_agent_capability(conn, *, agent_id, capability) -> bool`. 러너 등록이 만드는 `code.fix`·`code.review`·`code.triage` 는 이 경로로 떼지 못한다(내장 종류 능력 보호 — 거부). 기존 `upsert_agent`·`POST /operator/agents`(전체 덮어쓰기)는 바꾸지 않는다. 범위 값: 에이전트의 기존 내장 능력 scope 의 `repository_id`(러너 에이전트는 저장소 하나) — 없으면 그 에이전트는 체크박스에서 고를 수 없다(이유 표시).
6. **종류 폼.** 기본 칸 = 화면 이름(필수) · 지시문 · 결과값(쉼표, 기본 채움 값은 step 0) · 맡을 에이전트(체크박스, 에이전트 이름 · 저장소 · 소유자의 Mac). "고급" 접힘 = 종류 식별자(비우면 자동) · 능력 코드(비우면 종류 식별자) · scope_key(기본 `repository_id`) · 받는 산출물. 자동 식별자 규칙은 step 0(추천: `k_` + 소문자 hex 6자, `KIND_PATTERN` 안, 충돌 시 다시 뽑기). 등록과 능력 붙이기는 한 트랜잭션. 종류 삭제 시 그 종류 능력을 모든 에이전트에서 뗀다(같은 트랜잭션). 내장 종류 카드는 이름·받는/내는 산출물 라벨만 보이고 코드는 "자세히".
7. **팀 화면.** 절 순서: 멤버 → 초대 → 에이전트 → 담당 범위. 에이전트 표 한 줄 = `이름 · <소유자>의 Mac · 켜짐|꺼짐(마지막 확인) · 맡을 수 있는 일(종류 화면 이름들) · 맡기기 정책` — 러너 표를 이 표에 합친다(러너 [해제] 는 그 에이전트 줄의 동작). 에이전트별 "맡을 수 있는 일" 편집(사용자 정의 종류 체크박스 — 5 의 함수) 은 관리자에게만. ID·능력 코드·connector id 는 줄의 "자세히" 접힘 안. 담당 범위 폼: "시스템"(넓은 입력, 소문자 식별자 규칙을 placeholder·help 로) · "요청 유형"(고르는 목록 — 고정 목록은 step 0 이 RESPONSIBILITY_DIRECTORY 에서 정함) · 받는 사람 · 판단 담당자 · 조사 에이전트(이름만). 표에는 멤버·에이전트 **이름**만.
8. **저장소 화면.** 카드 = 저장소 이름 · 수집 상태 · `업무 N건 보기`(→ `/tasks?repo=owner/name`) · 본문 칸 **판단 에이전트**(설명: "새로 들어온 업무의 담당·종류를 제안하고, 결과가 규칙 밖이거나 정보가 모자라거나 사내 요청이 돌아오면 다음 단계를 제안합니다") · 수정·검토 에이전트(이름만) · 실행 방식. "고급" 접힘 = 로컬 저장소 ID · 수정 검증 프로필 · 트리거 라벨 · 재작업 상한 · 담당 연결. 카드 안 이슈 목록·[에이전트에게 맡기기] 줄은 뺀다(업무 화면이 한다). 담당 연결의 "GitHub 사용자 숫자 ID" 입력은 수집한 이슈에서 본 GitHub 사용자 고르기로 바꿀 수 있는지 step 0 이 확인(안 되면 고급에 두고 라벨만 정리). Jira 연결·GitHub App 연결 버튼은 이 화면.
9. **업무 목록.** 끝난 업무(`TERMINAL_WORK_STATUSES`)는 어떤 묶기에서도 맨 아래 "끝난 업무" 묶음으로 — 빠른 필터 건수와 묶음 머리 건수가 같은 기준이 된다. 화면에 보이는 행이 모두 같은 값인 칸(우선순위·종류)은 숨긴다(보드 카드도). 다음 할 일 문구가 상태 이유와 같으면 비운다(`—`). 도구 막대 = 빠른 필터 · 저장소 select · [업무 등록] + "보기 옵션" 접힘(묶기·목록/보드·끝난 업무). 저장소 select 는 바꾸면 바로 이동(소량 JS), JS 없으면 `<noscript>` 안 [보기] 버튼.
10. **설정 화면.** 탭 = 업무 종류·규칙 · 판단 · 알림 · n8n 입구 · 고급. n8n 입구(지금 "가져올 곳" 탭 아래 토큰·curl)는 별도 탭. 각 탭에서 내부 ID·코드는 "자세히" 안으로만(고급 탭은 예외 — 수동 등록 폼은 그대로).
11. **검증 기준.** 팀·저장소·설정 화면과 업무 목록 본문에 `agt-[0-9a-f]`·`conn-[0-9a-f]`·`inv-[0-9a-f]`·`code\.(fix|review|triage)` 이 "자세히"(`<details class="detail">` 등 step 0 이 정한 표식) 밖에 나오지 않는다. 표는 가로 스크롤 컨테이너 안에 있다(390px 에서 페이지 가로 스크롤 없음 — CSS·마크업 단정).

## 하지 않는 것

저장소별 판단 기준, 관리자의 "멤버로 보기", 초대 이메일 발송(SMTP), 링크 원본 보관, 에이전트 능력 일괄 편집 API(JSON), 러너 프로토콜 변경(러너 재설치 불필요), 업무 패널·단계 상세·`/requests` 화면 재설계(점검 범위 밖), 새 의존성(JS 프레임워크·CSS 프레임워크·아이콘 라이브러리), 실제 GitHub·Claude·Jira·Discord 호출, K1 실연동(phase 뒤 사용자 지시).
