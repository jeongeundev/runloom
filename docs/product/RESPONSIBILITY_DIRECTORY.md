# 담당 범위 표 — 첫 구현

2026-10-03. [요청 계약 설계](INTERNAL_REQUEST_CONTRACT_DESIGN.md)의 담당표 등록·후보 조회·명시적 선택 확인을 구현했다. 웹 관리 화면과 [요청 생성·수락](INTERNAL_REQUESTS.md)까지 연결했다.

## 동작

워크스페이스별로 시스템 식별자·요청 종류·수신 멤버·판단 담당 멤버·선택적 에이전트를 등록한다. 같은 시스템과 요청 종류에 여러 수신자를 둘 수 있다. 후보가 한 명이어도 사람이 선택해야 한다.

시스템 식별자와 요청 종류는 소문자 식별자다. 파일 경로·명령으로 사용하지 않는다. 요청 종류는 담당표 조회용 분류이며 실행용 `KindSpec` 등록과 별개다. 실제 조사 착수 단계에서 업무 종류·능력·scope·사용 승인·온라인 상태를 검사해야 한다.

등록·교체 때 담당자 둘은 같은 워크스페이스의 활성 멤버여야 한다. 에이전트는 같은 워크스페이스에 등록되어야 한다. 이후 비활성화·등록 해제가 발생하면 후보 조회에서 선택 불가와 이유를 보여주고 선택 요청을 거부한다. 표를 자동 삭제하지 않아 운영자가 변경 이유를 확인할 수 있다.

등록은 `manage_rules`, 조회는 로그인 멤버, 선택 확인은 `delegate` 권한을 사용한다. 판단 담당자 등록은 이후 판단 요청의 대상 정보이며 새로운 권한 부여가 아니다.

## API

| 경로 | 의미 |
|---|---|
| `GET /responsibilities` | `config_revision`, `entries` 조회 |
| `PUT /responsibilities` | `expected_revision`, `entries`로 전체 교체 |
| `GET /responsibilities/candidates?system_id=billing&request_kind=investigation` | 해당 후보와 `selectable`·`reason`, 항상 `selection_required=true` |
| `POST /responsibilities/select` | 시스템·종류·수신 멤버·`expected_revision`을 받아 현재 선택 유효성 확인 |

항목 예시:

```json
{
  "system_id": "billing",
  "request_kind": "investigation",
  "recipient_member_id": "등록한 멤버 ID",
  "judgment_member_id": "등록한 멤버 ID",
  "agent_id": null
}
```

`PUT`은 최대 200행, 같은 시스템·종류·수신자 중복을 거부한다. 전체 검증과 저장·설정 번호 증가를 한 트랜잭션으로 처리한다. 오래된 설정 번호는 409 `stale_directory`; 부적합 항목은 422 `invalid_field`다. 변경 기록은 기존 `mapping` 영역에 ‘담당 범위 표 N행’으로 남긴다.

선택 API는 확인용이며 선택을 저장하거나 원업무 담당·Task·Execution·사용 승인을 변경하지 않는다. 응답은 `config_revision`·선택된 `entry`·`execution_started=false`다. 이 응답이 이후 실행 권한을 보장하지 않으므로 요청 생성·착수 시 조건을 다시 검사해야 한다.

## 저장과 검증 범위

스키마 v17은 워크스페이스별 담당표를 추가한다. v16 이하 지원 DB는 기존 마이그레이션 다음에 빈 담당표를 추가한다. 기존 조직의 담당을 추정해서 채우지 않는다. 운영 DB에는 이번 작업에서 직접 연결하거나 마이그레이션을 실행하지 않았다.

테스트는 빈 후보·복수 후보·활성 멤버·에이전트 등록 해제·다른 워크스페이스·중복·설정 충돌·역할 제한·선택 시 업무/실행 불변·마이그레이션 데이터 보존을 확인한다. 담당표만으로 실제 부서 격리나 협업 효과가 검증되지는 않는다.

후속 [요청 생성·수락](INTERNAL_REQUESTS.md)은 이 표의 대상을 확인하여 요청으로 보존한다. 조사 실행과 결과 반환은 다음 단계다.

## 웹 관리 화면

`/connect?tab=team`에서 담당 범위 표를 조회한다. 관리자는 시스템·요청 유형·수신자·판단 담당자·선택적 에이전트를 한 행씩 추가하거나 삭제한다. 변경하려면 삭제 후 다시 추가한다. 일반 멤버는 조회만 할 수 있다. 비활성 멤버와 해제된 에이전트를 참조하는 기존 행은 사용 불가 사유를 표시한다. 저장 시 화면의 설정 revision을 검사하므로 다른 변경이 있으면 새로 조회해야 한다.

이 화면의 등록은 실행이나 권한 부여를 발생시키지 않는다. 업무 상세에서 별도로 요청을 보내야 한다.
