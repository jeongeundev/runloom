# 정보 부족 질문과 답변

2026-10-04. [담당 아님·명시적 재전달](INTERNAL_REQUEST_REROUTING.md)에 이어, 수락한 요청에서 부족한 정보를 질문하고 원래 요청자가 답변하는 흐름을 구현했다.

## 사용자 흐름

1. 지정 수신자가 받은·보낸 요청 화면에서 수락한 요청에 정보 질문을 보낸다. 한 요청에 미답변 질문은 한 개만 둔다.
2. 요청 화면과 원업무에 ‘정보 답변 대기’와 질문이 표시된다. 원래 요청자에게 답변 양식이 표시된다.
3. 요청자가 답변하면 질문·답변과 각 작성자·시각이 보존된다. 필요하면 다음 질문을 보낼 수 있다.
4. 새 조사 실행에는 그때까지 답변된 질문·답변이 원래 목적과 함께 포함된다. 이미 생성된 실행 봉투는 바뀌지 않는다. 답변만으로 새 실행을 만들거나 결과를 승인·반환하지 않는다.

미답변 질문이 있으면 조사 Task 생성, 대기 중인 Task의 새 실행, 사람 검토를 통한 재실행, 결과 반환을 막는다. 이미 실행 중인 에이전트를 취소하거나 중단하지 않는다. 러너·소유자 승인 때문에 대기하던 Task는 답변 후 기존 워커의 재시도 경로로 시작할 수 있다.

조사 결과가 이미 나온 뒤에도 반환 전에 질문할 수 있다. 이 경우 답변이 기존 결과에 자동 반영되지는 않는다. 수신자가 기존 결과와 새 답변을 확인해 재실행 또는 반환을 선택한다. 검토·계약 검증·지정 수신자의 반환 조건은 유지한다. 결과 반환 후 새 질문은 막는다.

질문은 사람의 추가 정보 요청이다. 모델 결과의 `needs_information`을 자동으로 질문으로 변환하거나, 지정 판단 담당자에게 업무상 결정을 요청하는 기능은 후속 범위다. 질문 내용으로 명령이나 로컬 경로를 실행하지 않는다.

## API와 버전

- `POST /internal-requests/{id}/questions`: `expected_revision`(요청 버전), `submission_key`, `text`. 응답 권한과 지정 수신자를 검사하고 수락·반환 전 상태를 확인한다.
- `POST /internal-requests/{id}/questions/{question_id}/answer`: `expected_revision`(질문 버전), `text`. 응답 권한과 원래 요청자를 검사한다. 다른 요청의 질문 ID는 찾을 수 없는 질문으로 처리한다.
- GET·POST의 요청 응답은 `questions` 배열과 `waiting_for_information`을 포함한다. 접수 키는 응답에 노출하지 않는다.
- 질문·답변은 요청의 수락·조사 버전을 증가시키지 않는다. 질문 자체의 버전은 미답변 1, 답변 완료 2다. 따라서 정보 왕복 후에도 기존 조사 착수·결과 반환 재시도 계약을 유지한다.
- 같은 접수 키와 질문은 기존 기록을 반환한다. 같은 키의 다른 질문은 충돌한다. 같은 답변의 재시도는 기존 기록을 반환하며, 다른 답변으로 덮어쓰기는 허용하지 않는다. 기존 기록 재시도는 현재 요청 이력을 반환하므로 이후의 답변·질문도 포함될 수 있다.
- 질문·답변은 최대 4,000자이며 공백만 있는 입력과 추가 필드를 거부한다. 질문 접수 키는 최대 128자다.

## 저장과 검증

스키마 v21은 `internal_request_questions`를 추가한다. 질문 ID, 요청 ID, 접수 키, 질문·답변, 작성자와 시각, 질문 버전을 저장한다. 요청별 접수 키 UNIQUE와 미답변 질문에 대한 부분 UNIQUE 인덱스를 둔다. 쓰기 트랜잭션에서 수신자·요청자·버전·중복·미답변 상태를 검사한다. 기존 요청·반려·조사 기록은 재생성하지 않는다. v4~v20 마이그레이션은 v21까지 이어진다.

합성 자료로 API·화면·이스케이프, 권한·오래된 버전·입력 검증, 동시 제출과 재시도, 질문 순서, 실행 맥락, 러너 대기, 기존 실행 보존과 결과 반환 차단, 검토 재실행 잠금 보존, 마이그레이션을 검증했다. 실제 AI CLI 실행과 회사의 왕복 시간 감소는 아직 검증하지 않았다. 운영 DB·러너에는 적용하지 않았다.
