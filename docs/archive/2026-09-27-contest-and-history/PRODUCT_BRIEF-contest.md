## MVP와 공모전

> 상태 (2026-09-21): 2026-09-21 이후 공개 데모는 대본 에이전트([ADR-0008](../adr/0008-public-demo-scripted-agents.md)). [PRD](../PRD.md) 시연 흐름의 등록·가져오기·구성·자동 실행은 구현됨, 실제 모델·실제 Codex 실행 증거는 [VERIFICATION_LOG](../VERIFICATION_LOG.md) 2026-09-20. 본문은 합의 기록이라 고치지 않는다.

최신 합의는 로컬 Codex 또는 Claude Code 1종과 사내 역할의 API 에이전트를 연결하는 구성이다. 실제 사내 에이전트가 없으므로 별도 데모 서비스를 준비한다. 개인 에이전트만 연결하는 방향으로 좁히지 않는다. 업무 입력은 서비스 내 등록이며 Jira 연동은 첫 MVP 필수가 아니다.

첫 시연은 일일 보고서 자동화에서 외부 응답 형식 변경으로 변환 코드가 실패한 사건이다. 사내 운영 진단 API 에이전트가 가상의 실행 이력·로그·운영 문서로 진단하고, 개인 개발 에이전트가 실제 데모 저장소에서 오류를 재현·수정·테스트한다. [미리디 AX Engineer – Infra 공고](https://www.miridih.com/ko/o/220034)의 운영 업무에서 착안했으며 해당 기업의 실제 구성·장애 사례가 아니다. 세부 데이터·인터페이스는 설계 전이다. 이 시연과 연결 대상은 사용자 합의다.

공모전 시나리오는 이 제품 가치를 보여주는 사용 장면이다. 제품 방향과 별개의 선택지가 아니다. 등록 과정과 기존 환경의 재사용을 보여주고, 이미 등록된 에이전트가 순서대로 실행되는 장면만으로 차별성을 주장하지 않는다.

구체적인 시연 제안과 수용 기준은 [PRD](../PRD.md)에 둔다. 공모전 제약(무로그인 웹 데모, 설치형 불가, 심사 기간 상시 접속)은 2026-09-20 적용을 확인해 [ADR-0000](../adr/0000-principles.md)에 기록했다.

OpenArchive 문서 플랫폼은 후속 연동 후보이며 첫 MVP 필수가 아니다. 사용자는 미사용·후속 도입을 허용했고, assistant는 작은 JSON·Markdown 자료와 조회 도구로 운영 진단을 시작하는 안을 제안했다. 범용 사내 에이전트 생성 기능까지 첫 범위로 확대하지 않는다.
