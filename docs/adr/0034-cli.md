# ADR-0034: 사람용 CLI `runloom` — 터미널의 에이전트가 내 다음 업무와 인계 리포트를 직접 가져가고, 결정 답·사람 요청 응답·직접 작업 시작까지 한다

결정일: 2026-10-27 (phase 26 step 0). 근거: [ADR-0031](0031-handoff-understanding-and-clients.md) 결정 3(API 우선)·6(순서 ③ "API 를 감싼 CLI — 에이전트가 '내 다음 업무와 인계 내용'을 직접 가져감"), [ADR-0032](0032-human-api-and-member-tokens.md)(사람용 API·멤버 토큰), [ADR-0033](0033-handoff-report.md)(인계 리포트), [PRD](../PRD.md) 수용 항목 "웹 화면 없이 API(또는 CLI)로 업무 조회·리포트 조회·결정 응답·착수가 됨". 결정 원본은 [phase 26 README](../../phases/26-cli/README.md) "결정" D1~D31 이고 이 문서가 구현 기준으로 고정한다. 이름·인자·출력·exit code·시그니처의 기준은 [ARCHITECTURE](../ARCHITECTURE.md) "CLI — phase 26" 이다(README 와 다르면 ARCHITECTURE). 예시는 [CONTRACT](../CONTRACT.md) 20절.

## 배경

- ① phase 24 로 사람용 기능이 `/api/v1` JSON API 와 멤버 토큰(`wfm_…`)으로 열렸고, ② phase 25 로 단계마다 근거가 붙은 인계 리포트(`GET /api/v1/reports/{report_id}`)가 생겼다.
- 그러나 터미널에서 Claude Code·Codex 를 켜 둔 사람이 "내 차례 업무가 뭐고, 앞 사람이 무엇을 왜 했는지" 를 에이전트에게 넘기려면 웹을 열어 복사해야 한다. curl 로 API 를 부를 수는 있지만 토큰 보관·여러 API 조합(업무 상세 + 리포트 목록 + 내 맞춤 풀이 고르기)·리포트 읽기 형태를 매번 사람이 맞춰야 한다.
- 이 ADR 은 ③ 이다. ④ IDE 앱은 별도 phase.

## 코드 조사로 README 와 달라진 사실 (2026-10-27, `feat-26-cli` = `main` `8ffcb01` + phase 파일)

[사용자] 결정과 충돌하는 코드 사실은 없다. 아래는 결정을 구현 이름으로 옮기며 확인한 것이고, 바꾼 것은 [근거]·[조정값] 의 구현 방식뿐이다.

1. **리포트 보기 묶음의 `stale` 은 단계가 아니라 원인 실행 기준이다.** `handoff_reports.report_view` 의 `stale` = "이 맞춤 풀이의 기준 원본이 **같은 원인 실행**의 최신 원본이 아님"(`repo.latest_original_report(conn, source_execution_id)`). 한 단계(원인 Task)에 재작업으로 원인 실행이 여럿이면, 이전 실행의 원본을 기준으로 한 맞춤 풀이는 `stale = false` 인데도 단계의 최신 원본 기준이 아니다. D16 [사용자] "기준이 최신 원본이 아니면 `옛 리포트 기준`" 을 지키려고 CLI 는 **`stale` 이 참이거나 `base_report_id` 가 펼친 원본의 `report_id` 와 다르면** `옛 리포트 기준` 을 붙인다(ARCHITECTURE "리포트 고르기"). 서버 `stale` 의 뜻은 바꾸지 않는다(웹 화면이 쓴다).
2. **리포트 목록 응답에는 맞춤 풀이의 단계·요청 멤버 id 가 없다.** `stage_reports` 의 `tailored` 는 (기준 원본, 요청 멤버)마다 최신 보기 묶음 목록이고, 단계는 `base_report_id` 가 그 단계의 `latest`·`previous` 중 어느 `report_id` 와 같은지로만 알 수 있다. 요청 멤버는 표시 이름(`requested_by`)뿐이라 이름이 같은 멤버를 가릴 수 없다 — 그래서 D28 이 `requested_by_member_id` 를 더한다. 단계 정보는 더하지 않는다(`base_report_id` 로 충분).
3. **리포트 목록의 `stages[].latest` 는 늘 있다.** `stage_reports` 는 원본 행이 있는 단계만 넣는다. ARCHITECTURE 표가 `latest(보기 묶음 또는 null)` 이라 적었으므로 CLI 는 null 을 건너뛰기만 한다.
4. **`GET /api/v1/human-requests` 는 워크스페이스의 열린 요청 전부를 돌려준다**(내 차례만이 아님, `request_id`·`task_id`·`code`·`question`·`revision`·`state`·`created_at`). `expected_revision` 은 그 `revision` 이고 서버는 `state != 'open'` 이거나 revision 이 다르면 409 `stale_request` 다. 응답은 `{request_id, task_id, response_id, task_revision, created}`. `ResponseBody` 는 `strict=True` 라 `text` 에 null 을 보내면 422 — CLI 는 `--text` 가 없으면 `""` 를 보낸다.
5. **`start_direct` 는 같은 멤버가 다시 부르면 처음 브랜치를 돌려준다**(멱등). 응답은 업무 상세이고 브랜치는 `direct.branch`. 에이전트 실행 중이면 409 `execution_conflict`.
6. **`/me` 를 둘 라우터.** `member_token_api.router` 의 접두어가 `/me/tokens` 라 그 라우터에 `/me` 를 둘 수 없다. 같은 파일에 두 번째 라우터 `me_router = APIRouter(prefix="/me")` 를 두고 `app.py` 가 따로 등록한다(기존 `/me/tokens` 경로·동작은 그대로).
7. **경계 검사는 이미 정규식 테스트가 있다.** `tests/test_packages.py` 가 `server`↔`connector` 상호 import 를 소스 정규식으로 검사한다. D5 의 새 AST 검사는 `tests/workflow/cli/test_boundary.py`(step 3)에 두고, `test_packages.py` 는 건드리지 않는다.
8. **리포트 절 제목·상태 문구는 웹 코드에 있다** — `web._REPORT_SECTIONS`(`바뀐 것`·`결정과 근거`·`정하지 않고 남긴 것`·`받는 사람이 결정·확인할 것`·`지킬 제약`·`남은 일`)와 `report.html`(`다이어그램`·`기록 없음`·`근거 확인 안 됨`·`리포트 작성 중`·`리포트 없음({reason})`·`옛 리포트 기준`, 상태 라벨 `완성`). `cli` 는 `server` 를 import 하지 않으므로 같은 글자를 `cli/render.py` 에 따로 둔다(D5).
9. **근거 확인 표시는 `evidence_check.claims[<주장 id>].verified`** 다. 근거가 비어 있어도 `verified = false` 라 `근거 확인 안 됨` 이 붙는다(웹과 같다).
10. **`role` 값은 `admin`·`member`** 둘이다. 로그인 문구는 번역 없이 이 값을 그대로 쓴다(`cli` 는 `domain.team` 을 import 하지 않는다).

## 결정

### 범위와 구조 (D1~D6)

1. **명령**은 `login`·`logout`·`list`·`next`·`show`·`report`·`decide`·`respond`·`start`·`stop` 열 개, 모두 `--json` 을 받는다. 맡기기·우선순위·판단 제안 수락/무시·맞춤 풀이 요청·리포트 다시 만들기는 하지 않는다 — 웹에서 한다(D1). 직접 작업(에이전트 실행 없는 업무)의 리포트는 다시 미룬다(D2, ADR-0033 이 ③ 으로 미룬 항목).
2. **서버 변경은 둘뿐**이다 — `GET /api/v1/me` 추가와 리포트 보기 묶음의 `requested_by_member_id`. 스키마 v27 그대로, 러너 프로토콜 그대로(D3·D28).
3. **위치**: 같은 패키지 `workflow` 안의 `src/workflow/cli/`. pyproject console script `runloom = "workflow.cli.main:main_entry"`, `python3 -m workflow.cli` 도 같다. 서버 의존성도 함께 깔린다 — 패키지 분리는 ④ 앱 때 다시 본다(D4).
4. **경계**: `workflow.cli` 는 `workflow.contracts`·HTTPX·표준 라이브러리만 import 한다. `server`·`connector`·`domain`·`adapters` 금지, 반대로 `server`·`connector` 도 `cli` 를 import 하지 않는다. AGENTS.md 아키텍처 규칙에 넣고 AST 경계 테스트로 지킨다. 테스트 코드는 서버 앱을 띄워도 된다(D5).
5. **테스트**: `tests/workflow/cli/`. `ApiClient` 가 `httpx.Client` 를 주입받고, 테스트는 실제 앱의 `TestClient` 를 넣어 계약 어긋남을 잡는다(D6).

### 인증·설정 (D7~D13)

6. **로그인**: `runloom login --server URL` 이 토큰을 표준 입력 첫 줄에서 읽고(명령 인자로 받지 않는다 — 셸 기록), `GET /api/v1/me` 로 확인한 뒤에만 저장한다. 성공 문구 `<이름>(<역할>, 토큰 <read|full>)로 로그인했습니다.`(D7).
7. **자격 파일**: `~/.config/runloom/credentials.json`(디렉터리 0700, 파일 0600, 임시 파일 → `os.replace`), 내용 `server`·`token`. `RUNLOOM_HOME` 이 있으면 `$RUNLOOM_HOME/credentials.json`, `XDG_CONFIG_HOME` 은 따르지 않는다(D7·D10). 읽을 때 그룹·다른 사용자 권한 비트가 있으면 거절하고 `chmod 600 <경로>` 를 안내한다(exit 2, D9).
8. **환경변수**: `RUNLOOM_TOKEN`·`RUNLOOM_SERVER` 가 있으면 파일보다 먼저, 각각 따로(D7).
9. **서버 주소**: `http://` 는 호스트가 `localhost`·`127.0.0.1`·`::1` 일 때만, 그 밖은 `https://` 만. 끝 `/` 는 지우고 경로·쿼리가 붙으면 거절한다. `login --server` 와 `RUNLOOM_SERVER` 모두 같은 규칙(exit 2, D11).
10. **로그아웃**: 로컬 자격 파일만 지우고 `서버의 토큰은 웹 /me 에서 폐기하세요.` 를 출력한다. 서버 폐기 API 는 부르지 않는다(D8).
11. **러너가 띄운 에이전트는 CLI 를 쓰지 않는다.** 러너는 `RUNLOOM_TOKEN`·`RUNLOOM_SERVER` 를 등록 `--env` 예약 이름(`connector/masking.py` `RESERVED_ENV_NAMES`)에 넣어 거절하고, 로그 마스킹에 `wfm_` 를 더한다. 실행 환경은 이미 허용 목록(`codex_env`)이라 상속으로는 새지 않는다(D12).
12. 러너 에이전트가 같은 Mac 의 자격 파일을 읽을 수 있는 문제는 다루지 않는다 — 러너 `token.json`(`wfc_`)과 같은 노출 수준이고 파일 시스템 격리는 범위 밖이다(D13).

### 동작 (D14~D25)

13. **`next`**: `GET /api/v1/work-items?filter=my_turn` 결과를 우선순위(`high` > `normal` > `low`) → `updated_at` 오래된 순으로 정렬해 1건을 `show` 와 같이 출력하고, 나머지가 있으면 `내 차례 n건 더 — runloom list --filter my_turn`. 없으면 `내 차례 업무가 없습니다.`(exit 0). 후보는 웹 `내 차례` 필터와 같은 뜻 — 내가 직접 작업 중인 업무는 아니다(D14).
14. **`show KEY`**: 업무 상세(키·제목·종류·우선순위·담당·상태·이유·다음 할 일·원본 링크·직접 작업 브랜치·열린 사람 요청과 `request_id`·허용 행동) + 리포트. 내 차례가 아닌 업무도 API 권한대로 본다(D15).
15. **리포트 고르기**: 최신 원본의 `created_at` 이 가장 늦은 단계 하나의 최신 원본을 펼치고, 그 단계 원본(최신·이전)을 기준으로 **내가 요청한** 맞춤 풀이 중 가장 최근 것이 있으면 함께 펼친다. 기준이 펼친 원본이 아니면 `옛 리포트 기준`(사실 1). 나머지 원본은 `단계 이름 · report_id · 상태` 한 줄씩, 하나도 없으면 `인계 리포트 없음`(D16). `done` 이 아니면 본문 대신 `작성 중`·`리포트 없음(사유)`(D17).
16. **`report REPORT_ID`**: 절별 주장·주장 id·근거 id·`근거 확인 안 됨`·`why` 없음은 `기록 없음`, 결정 항목마다 `item_id` 와 현재 답. 절 제목은 웹 리포트 페이지와 같은 한국어(D18).
17. **`decide REPORT_ID ITEM_ID (--confirm | --change TEXT)`** → `PUT /api/v1/reports/{id}/decisions/{item_id}`. 길이·답할 수 있는 사람 판정은 서버, 성공하면 바뀐 리포트를 `report` 와 같이 출력(D19).
18. **`respond REQUEST_ID ACTION [--text] [--agent]`** → `GET /api/v1/human-requests` 에서 `revision` 을 찾아 `expected_revision` 으로, `response_id` 는 명령 1회마다 새 uuid. 없으면 `열린 사람 요청 <id> 가 없습니다.`(exit 1). 행동 검사는 서버(D20).
19. **`start KEY`·`stop KEY`** → `PUT`·`DELETE /api/v1/work-items/{key}/direct-work`, 시작은 `브랜치: <이름>` 출력. 로컬 git 은 실행하지 않는다(D21).
20. **`list`**: `--filter`(기본 `all`)·`--repository`·`--closed`, 값 검사는 서버. 한 줄에 키·우선순위·상태·제목·담당(D22).
21. **출력**: 기본 한국어 텍스트(마크다운풍). `--json` 은 단일 호출이면 응답 본문 그대로, `show`·`next` 는 `{"detail", "reports", "report", "tailored"}`(+ `next` 는 `more_my_turn`), 업무가 없으면 네 키 모두 null·`more_my_turn` 0. `login --json` = `/me` 응답, `logout --json` = `{"deleted": bool}`(D23).
22. **오류**: `오류 <status> <code>: <message>` 한 줄을 stderr, exit 1. 401 이면 `runloom login 으로 다시 로그인하세요.` 를 덧붙인다. 네트워크 실패·시간 초과(30초) exit 1, 사용법·설정 오류 exit 2. 자동 재시도 없음, 응답의 모르는 키는 무시(D24).
23. **읽기 전용 토큰**의 행동 명령은 서버 403 `token_read_only` 를 위 형식 그대로 보인다. 대화형 프롬프트는 없다(`login` 의 표준 입력 제외, D25).

### 문서·운영 (D26~D31)

24. 에이전트가 CLI 를 아는 길은 `runloom --help`·명령별 `--help` 와 `docs/CLI.md` 뿐이다. Claude Code 스킬 등 도구 전용 파일은 만들지 않는다(D26).
25. Cloudflare Access 뒤 서버는 이번엔 지원하지 않고 `docs/CLI.md` 에 적는다(D27).
26. **`GET /api/v1/me`** → `{"member_id", "display_name", "role", "token_scope"}`(`token_scope` = `read`·`full`, 쿠키 로그인은 null), `require_member_api`(쿠키·`wfm_`, 읽기 전용 허용). 보기 묶음에 `requested_by_member_id`(원본 null) — 웹 템플릿은 쓰지 않는다(D28).
27. 다른 Mac 의 팀원 설치는 `python3 -m pip install "git+https://github.com/jeongeundev/runloom@<태그 또는 커밋>"`, 저장소 안은 `python3 -m pip install -e .`(D29).
28. 문서: 이 ADR, ARCHITECTURE "CLI — phase 26", CONTRACT 20절, GLOSSARY phase 26 용어, `docs/CLI.md`, AGENTS.md 아키텍처 규칙·명령어 줄, SELFHOST 업그레이드 메모(D30).
29. 셀프호스트 영향: `/api/v1/me` 때문에 서버 재설치(`install.sh`)가 필요하고 스키마는 그대로. 러너 재설치는 D12 반영을 원할 때만(D31).

## 결과

- 터미널의 사람·에이전트가 `runloom next` 한 줄로 내 차례 업무 하나와 그 업무의 최신 인계 리포트(와 내 맞춤 풀이)를 한국어 텍스트 또는 `--json` 으로 받고, 같은 CLI 로 결정 항목에 답하고, 사람 요청에 응답하고, 직접 작업을 시작·그만둔다.
- `next` 의 "오래 기다린 것" 은 `updated_at` 오래된 것으로 대신한다 — 웹 목록 순서(같은 우선순위에서 최근 변경 먼저)와 다를 수 있다.
- 셀프호스트는 `/api/v1/me` 때문에 서버 재설치(`install.sh`)가 필요하다. 스키마는 v27 그대로이고, 러너 재설치는 `RUNLOOM_*` 예약 이름·`wfm_` 로그 마스킹을 원할 때만이다. 절차는 [SELFHOST](../SELFHOST.md) "업그레이드"(step 6).
- CLI 와 서버가 같은 패키지라 다른 Mac 의 팀원도 서버 의존성(FastAPI 등)을 함께 설치한다. ④ 앱 때 패키지 분리를 다시 본다.
