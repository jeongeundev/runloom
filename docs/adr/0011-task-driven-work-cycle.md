# ADR-0011: 업무 목록과 결과 기반 후속 업무 순환을 제품 기준으로 삼는다

> 2026-09-23 확장: [ADR-0012](0012-delegated-decisions-and-pattern-feedback.md)에 따라 위임된 판단은 AI가 수행하며, 기존 작업 기록에서 패턴 발견·정형화와 도입 후 효과 검증을 지원한다. 아래 모호한 경우의 사람 확인은 허용된 조회·검토로 해결하지 못하거나 위임 범위 밖인 경우로 구체화한다.

결정일: 2026-09-22. 사용자 설명과 진행 합의에 따른 제품 방향 확정. 적용 대상은 `service`의 실서비스다. 이 결정의 새 동작은 아직 구현되지 않았으며, 공개 데모 `main`의 동작·배포를 바꾸지 않는다.

## 문제와 결정

목표는 업무 사이의 사람 중계와 착수 대기를 줄이는 것이다. 업무를 등록하거나 GitHub·Jira 같은 기존 업무 도구에서 가져오면 목록으로 관리하고, 업무별 입력·담당자·위임 범위를 확인해 실행 가능한 일부터 담당자의 기존 에이전트로 진행한다. 결과를 기존 업무의 입력으로 연결하거나 필요한 후속 업무를 생성하고, 다시 배정·실행 조건을 평가한다. 결과 기반 후속 업무 생성은 제품의 핵심 동작이며 선택적 장기 아이디어로만 취급하지 않는다.

1. 목록의 업무들을 하나의 직렬 체인으로 제한하지 않는다. 독립적인 업무는 다른 업무의 사람 대기에 막히지 않는다. 실제 동시 실행은 가용 자원과 작업 충돌 제약을 따른다.
2. 입력은 목표·역할·담당자·작업 대상·필요 자료·완료 기준을 포함한다. 기존 티켓·조직 정보·등록 규칙으로 채울 수 있는 정보는 재사용하고, 실행에 필요한데 불명확한 정보만 요청한다. 구체적인 추출 방식은 별도 기술 설계 대상이다.
3. 자동 실행은 필요한 입력·선행 조건·권한·위임 범위·실행 환경이 충족될 때 한다. 판단 자체를 모두 사람에게 넘기지 않는다. 위임 범위를 벗어나는 결정·승인·의견 조율은 필요한 사람에게 요청하고, 응답 후 조건을 다시 평가한다. 직접 실행 설정은 유지한다.
4. 결과는 산출물·검증 근거·남은 문제와 필요한 후속 작업 정보를 전달한다. 에이전트가 제안한 담당자·작업은 조직의 담당 관계와 허용 범위에 대조한다. 기존 대응 업무가 있으면 연결하고, 없고 생성 조건을 충족하면 새 업무를 만든다. 모호한 경우 사람에게 확인하며, 모델의 제안 자체가 권한을 부여하지 않는다.
5. 생성·인계에는 원인이 된 Task·Execution·결과 버전을 남긴다. 동일 결과 재처리로 업무나 실행이 중복되지 않아야 한다. 불필요한 반복 생성의 감지·중단과 재개 기준은 구현 전에 설계한다.
6. 결과 제출·형식 검증·업무 품질 검증·사람 승인을 구분한다. 다음 작업의 성격과 위임 조건에 따라 승인 전 검토·분석은 진행할 수 있고, 승인이 필요한 외부 반영은 기다린다.
7. 차별성은 기존 담당 체계와 서로 다른 기존 에이전트를 활용해 이 순환에서 사람의 재작성·전달·실행 조작을 줄이는 경험으로 검증한다. 독점적 기능이나 시장 유일성을 주장하지 않는다.

## 기존 결정과의 관계

| 문서 | 유지하는 내용 | 변경하거나 범위를 한정하는 내용 |
|---|---|---|
| ADR-0000 | 증거 기반 상태, 중복 방지, 최소 권한, TDD | A → B는 첫 검증의 역사적 범위이며 실서비스의 최종 범위가 아님 |
| ADR-0004 | 현재 중앙의 규칙 기반 실행 판정 | 입력 해석·후속 작업 제안 주체는 후속 설계에서 결정. 이번 결정으로 중앙 LLM 호출을 도입하지 않음 |
| ADR-0009 | 종류·입출력 봉투·등록 규칙·결과 보존 | 미리 등록된 후속만 잇는 것은 phase 6의 구현 한계. 업무 생성과 목록 단위 진행을 제품 범위에 포함. 승인 전 진행은 후속 업무의 위임 조건에 따름 |
| ADR-0010 | 현재 n8n 입구·callback 계약과 구현 | n8n을 입구·출구로만 제한하는 것은 영구 제품 원칙이 아님. 더 넓은 역할이나 워크플로우 생성 채택은 아직 결정하지 않음 |

n8n과 Runloom의 실행 책임을 중복시키지 않는다. 현재는 Runloom이 에이전트 실행 상태와 인계를 관리한다. 역할 변경은 별도 기술 설계·계약 변경으로 결정하고, 제품 목표와 기존 구현 사실을 구분한다.

## 검증과 다음 설계

[PRD의 실서비스 수용 기준](../PRD.md#실서비스-업무-순환--2026-09-22-확정)을 기준으로, 5개 업무 중 2개 자동 착수 → 결과로 기존 업무 연결·새 업무 생성 → 담당 에이전트 실행 → 사람 응답 후 재개의 전체 순환을 검증한다. 테스트용 대역을 이용한 계약 검증과 실제 에이전트·외부 업무 도구를 이용한 효과 검증을 구분한다.

담당자와 Agent의 연결 모델, 입력 해석 주체, 의존 관계, 사람 요청·응답, 후속 업무 중복 판정, 생성 반복 제한, 외부 티켓 동기화 및 DB 마이그레이션은 후속 설계 사항이다. 미확정 필드를 계약 v1이나 현재 코드 식별자로 기재하지 않는다. 구현 순서는 [ARCHITECTURE의 전환 설계](../ARCHITECTURE.md#실서비스-전환-설계--adr-0011)를 따른다.
