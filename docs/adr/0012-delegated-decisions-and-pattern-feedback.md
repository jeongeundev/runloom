# ADR-0012: 위임된 AI 판단과 작업 이력 기반 자동화 개선

> 출시 범위 구체화(2026-09-23): [ADR-0013](0013-existing-tasks-first-staged-rollout.md). 기록 분석은 선택적 설정 보조이며 필수 온보딩이 아니다. 기본 실행 기록은 초기부터, 패턴 추천·고급 모니터링은 반복 사용 후 단계적으로 제공한다. 아래는 전체 제품 방향이며 MVP 전체 요구가 아니다.

결정일: 2026-09-23. 사용자 확정 제품 방향. ADR-0011을 확장한다. 실서비스 `service` 대상이며 아래 새 동작은 미구현이다.

## 결정

1. 위임된 판단은 AI가 수행하고 조건을 충족하면 사람 확인 없이 실행한다. 위임 범위 밖이거나 허용된 추가 조회·전문 에이전트 검토로도 해결하지 못하면 사람에게 요청한다. 모호하다는 이유만으로 곧바로 사람에게 넘기지는 않는다.
2. 생성형 에이전트는 작업·복잡한 분석·후속 업무 제안을 맡고, 판단 모델은 주어진 후보의 선택·평가에 활용할 수 있다. Jev는 후보이며 채택·공급자·호출 위치·임계값은 미확정이다. 모델 선택과 제품 방향을 결합하지 않는다.
3. 서비스는 권한·허용 행동·필수 승인·예산·재시도·후속 생성 한도·중복 방지를 강제한다. 모델이 위험도를 낮게 평가하거나 confidence가 높아도 이 조건을 해제하지 않는다. 모든 업무에 동일한 사람 승인 절차를 강제하지 않는다.
4. 연결이 허용된 기존 서비스의 업무 이력, 개인 작업 기록, 접근 가능한 LLM 메모리에서 반복 패턴과 대기 구간을 발견하고 자동화 후보를 제안한다. 모든 도구의 비공개 메모리나 내부 추론에 접근할 수 있다고 가정하지 않는다. 명시적으로 제공된 기록·내보내기·공개 인터페이스만 대상으로 한다.
5. 패턴 후보는 시작 조건, 필요한 입력, 담당 역할, 행동과 후속 조건, 예외, 완료·검증 기준, 근거 이력과 관찰 범위를 정형화한다. 과거에 수행한 행동이 곧 허용된 정책은 아니다. 개인의 습관을 조직 전체 규칙으로 자동 승격하지 않으며, 실패·재작업·예외도 근거로 포함한다.
6. 발견 → 정형화 → 과거 이력 재생·실행 없는 비교 → 위임 범위 안의 제한 적용 → 모니터링 → 유지·수정·중단을 지원한다. 승인된 범위 안의 개선은 정책에 따라 자동 적용할 수 있으나, 권한이나 자동 실행 범위 확대는 그 권한을 가진 사람의 결정을 따른다. 적용 버전과 근거를 남기고 이전 버전 복귀를 지원한다.
7. 도입 전 기준과 도입 후 인계 대기·전체 처리 시간·사람 중계 및 예외 요청·오배정·재작업·비용을 비교한다. 처리량 증가만으로 성공을 판정하지 않는다. 업무 종류·난이도·관측 기간·표본 수와 품질 변화를 함께 표시하고, 비교 불가능하거나 기록이 부족하면 효과 판단 불가로 남긴다.

## 범위와 기존 결정

로그 기반 패턴 정형화는 모델 가중치의 재학습을 뜻하지 않는다. 첫 접근은 기록에서 후보 규칙·업무 템플릿·판단 기준을 추출해 실행 시 참조하는 것이다. 별도 모델 학습은 결정하지 않았다. 이력이 없는 사용자도 직접 등록·규칙 설정으로 시작할 수 있다.

ADR-0004의 중앙 모델 미호출은 현재 구현 설명으로 유지하되, 실서비스에서 AI 판단을 제외하는 영구 원칙으로 사용하지 않는다. 실제 호출을 추가하기 전에 호출 경계·비용·데이터 전달·검증 및 실패 처리를 기술 설계한다. 이번 결정은 모델 설치·유료 호출·실제 기록 수집을 수행했다는 뜻이 아니다.

ADR-0011의 업무 순환은 유지하고, 사람 개입 경계와 도입 전후 개선 순환을 확장한다. 현재 계약 v1·스키마·공개 데모는 변경하지 않는다. 수용 기준은 [PRD](../PRD.md)의 2026-09-23 확장 절을 따른다.
