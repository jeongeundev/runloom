# ADR-0013: 기존 업무에서 시작하고 기록 기반 설정 보조는 단계적으로 제공한다

결정일: 2026-09-23. 사용자 확정 방향을 반영한다. 버전별 세부 계획은 [제품 로드맵](../product/ROADMAP.md)의 제안이며 날짜·구현 완료를 뜻하지 않는다.

## 결정

- 초기 경험은 GitHub·Jira 등 기존 업무 가져오기 또는 직접 등록 → 담당 Agent 연결 → 준비된 업무 실행 → 원본 결과 반영 → 후속 연결·생성이다. 기존 서비스의 정보를 다시 작성하고 실행을 중계하는 부담을 줄인다.
- 자연어로 임의 워크플로우 전체를 생성하는 기능을 초기 제품의 약속·필수 화면으로 두지 않는다. 내부의 자연어 해석·AI 판단은 유지한다.
- 기록 없이도 시작할 수 있다. 기존 기록이 있으면 설정을 돕는 기능으로 활용하며, 로그 분석을 필수 첫 단계로 요구하지 않는다.
- 초기부터 입력·판단·결과·대기·개입 기록을 남긴다. 기록 기반 추천·패턴 발견·효과 분석 제품 기능은 반복 사용과 필요성을 확인한 뒤 제공한다. 로그가 쌓였다는 이유만으로 모델 재학습이나 고객 간 원문 공유를 전제하지 않는다.
- ADR-0011의 결과 기반 후속 업무 생성은 좁은 업무 유형으로 MVP부터 검증한다. ADR-0012의 위임 판단은 유지하고, 패턴 분석·개선은 장기 범위와 초기 필수 기능을 구분한다. 특정 판단 모델은 필수로 고정하지 않는다.

## 이유와 적용

사용자가 이미 사용하는 업무 서비스·담당 체계와 에이전트를 활용하는 것이 출발점이다. 기능을 모두 갖춘 뒤 도입하는 대신, 좁은 업무 순환의 유용성을 먼저 검증하고 실제 불편과 로그로 다음 기능을 결정한다.

기존 문서의 분석 → 정형화 → 자동화 순서는 기록을 활용하는 선택 경로로 해석한다. 현재 계약·코드·배포는 변경하지 않는다. 상세 버전 범위와 벤치마킹 방법은 ROADMAP, 현재 구현과의 간극 및 수용 기준은 PRD를 따른다.
